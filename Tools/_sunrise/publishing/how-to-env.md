# ENV для публикации сборок

[Где вводить переменные и секреты](../how-to-env.md). Примеры ниже относятся к Sunrise; у другого проекта должны быть свои идентификаторы сборок.

## Заполнить в GitHub

| Имя | Где и когда нужно | Что указать |
| --- | --- | --- |
| `ROBUST_CDN_URL` | Переменная GitHub; всегда | Адрес сервера раздачи сборок, например `https://cdn.finland.ss14.org`. Нужен HTTPS, без логина, пароля и параметров после `?` или `#`. Не добавляйте `/fork/...`. |
| `PUBLISH_FORK_ID` | Переменная GitHub; обычная публикация | Идентификатор обычной сборки на сервере раздачи: `sunrise_station`. |
| `PUBLISH_STABLE_FORK_ID` | Переменная GitHub; стабильная публикация | Идентификатор стабильной сборки: `sunrise_station_stable`. |
| `PUBLISH_TEST_FORK_ID` | Переменная GitHub; тестовая публикация | Идентификатор тестовой сборки, например `test_sunrise`. |
| `PUBLISH_TOKEN` | Секрет GitHub; всегда | Ключ загрузки сборок на сервер раздачи. Вставьте только ключ, без слова `Bearer`. |
| `MAKURA_PRIVATE_REPO` | Секрет GitHub; при включённом приватном содержимом | Имя закрытого репозитория в формате `владелец/репозиторий`, без адреса сайта и `.git`. |
| `MAKURA_PRIVATE_REPO_SSH_KEY` | Секрет GitHub; вместе с предыдущим | Полный закрытый SSH-ключ с доступом на чтение этого репозитория, включая начальную и конечную строки ключа. |
| `ANNOUNCE_UPDATE_DISCORD_WEBHOOK` | Секрет GitHub; для уведомления об обновлении Stable | Полный закрытый адрес отправки сообщений в нужный канал Discord. |
| `ANNOUNCE_UPDATE_DISCORD_ROLE_ID` | Секрет GitHub; для того же уведомления | Числовой ID роли, которую нужно упомянуть. Без одного из двух значений уведомление пропускается. |

Используйте **Publish Sunrise**, **Publish Stable** или **Publish Test**. Обычная публикация по умолчанию не добавляет приватное содержимое; Stable и Test добавляют. Stable запускается только из ветки `stable`.

## Передаются автоматически

Эти имена нужны для понимания запуска скриптов; отдельные переменные репозитория для них создавать не нужно.

| ENV | Откуда берётся и что означает |
| --- | --- |
| `PUBLISH_FORK_ID` | Для скрипта выбирается соответствующий ID: обычный, стабильный или тестовый. |
| `COMMIT_HASH` | Поле запуска `commit_hash`: идентификатор версии кода из 40 символов, то есть полный хеш коммита. Пустое значение означает версию на момент запуска. |
| `PRIVATE_COMMIT_HASH` | Поле `private_commit_hash`, а у Test — `private_ref`. Допускается полный хеш либо `master`/`stable`; пустое значение выбирает основную ветку закрытого репозитория. |
| `USE_PRIVATE_CONTENT` | Поле `use_private_content`: `true` включает приватное содержимое, `false` выключает. |
| `PRIVATE_REPOSITORY`, `PRIVATE_REPOSITORY_SSH_KEY` | Значения двух секретов `MAKURA_PRIVATE_REPO*` для проверки настроек перед сборкой. |
| `CURRENT_REF_NAME`, `CURRENT_REF_TYPE` | Имя выбранной ветки и тип ссылки. Для обычного запуска без хеша разрешены ветки `master` и `stable`. |
| `SERVER_PLATFORMS` | Список систем, для которых собирается сервер, например `--platform linux-x64`. Выбирается сценарием публикации. |
| `DISCORD_WEBHOOK_URL`, `DISCORD_ROLE_ID`, `BUILD_PATH` | Адрес Discord, роль и путь к архиву. [Подробности уведомления](../how-to-env.md). |

## Отдельный скрипт загрузки артефакта

`publish_github_artifact.py` не вызывается обычной публикацией. При его отдельном запуске дополнительно нужны:

| ENV | Значение |
| --- | --- |
| `ARTIFACT_ID` | Числовой ID сохранённого архива сборки в GitHub Actions. |
| `GITHUB_TOKEN` | Ключ GitHub, которому разрешено читать этот архив. |
| `GITHUB_REPOSITORY` | Репозиторий с архивом: `makura-games/sunrise-station`. |
| `GITHUB_SHA` | Полный хеш коммита, из которого собран архив. Именно он будет записан как версия. |

Также нужны `ROBUST_CDN_URL`, `PUBLISH_FORK_ID` и `PUBLISH_TOKEN` из первой таблицы. Для обычной публикации версия определяется по собираемому коду автоматически.

Настройки списка изменений находятся [в разделе чейнджлога](../changelog/how-to-env.md). Переменная `PUBLISH_CHANGELOG_FILE` не используется.
