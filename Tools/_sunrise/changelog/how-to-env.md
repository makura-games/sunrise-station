# ENV для чейнджлога

Чейнджлог — список изменений для игроков. Его создание в репозитории и отправка в Discord настраиваются отдельно. [Где вводить настройки](../how-to-env.md).

## Заполнить в GitHub

| Имя | Где и когда нужно | Что указать |
| --- | --- | --- |
| `CHANGELOG_FILE` | Переменная GitHub; создание и проверка списка | Путь от корня проекта, например `Resources/Changelog/ChangelogSunrise.yml`. Для другого проекта выберите его файл. |
| `CHANGELOG_EXTRA_CATEGORIES` | Переменная GitHub; необязательно | Дополнительные категории латиницей через запятую, например `Admin,Maps`. Их файлы лежат рядом с основным чейнджлогом. Пустое значение оставляет только основную категорию. |
| `CHANGELOG_APP_CLIENT_ID` | Переменная GitHub; автоматическая запись изменений | Идентификатор приложения GitHub, от имени которого сохраняются изменения. Выдаётся при настройке этого приложения. |
| `CHANGELOG_APP_PRIVATE_KEY` | Секрет GitHub; вместе с предыдущим | Полный закрытый ключ того же приложения. Приложению нужен доступ к репозиторию: запись содержимого и чтение запросов на слияние. |
| `CHANGELOG_DISCORD_WEBHOOK_SUNRISE` | Секрет GitHub; отправка цели `sunrise` в Discord | Закрытый адрес отправки сообщений в канал. Именно это имя сейчас записано в `targets/sunrise.yml`. Для остальных целей имя секрета берётся из их файлов. |

Файл для Discord выбирается через [реестр целей](targets/how-to-env.md), а не через `CHANGELOG_FILE` из настроек репозитория. Для одной цели пути обычно должны совпадать. Секрет `CHANGELOG_DISCORD_WEBHOOK` не заменяет автоматически `CHANGELOG_DISCORD_WEBHOOK_SUNRISE`.

## Передаются при запуске

В GitHub эти значения заполняются автоматически. При отдельном запуске скрипта на компьютере соответствующие значения нужно передать через терминал.

| ENV | Назначение и источник |
| --- | --- |
| `GITHUB_TOKEN` | Ключ доступа к GitHub: приложение выдаёт его для записи чейнджлога; сценарии проверки и Discord получают ключ для чтения. |
| `ACTIONS_TOKEN` | Отдельный ключ для чтения истории запусков при создании чейнджлога. Передаётся сценарием из стандартного ключа GitHub. |
| `GITHUB_REPOSITORY` | Имя репозитория, например `makura-games/sunrise-station`. |
| `GITHUB_RUN_ID` | Числовой номер текущего запуска. Нужен для сопоставления с предыдущими публикациями. |
| `GITHUB_EVENT_PATH`, `GITHUB_EVENT_NAME` | Файл с данными события и его тип; позволяют узнать, какой запрос на слияние обрабатывается или что запуск ручной. |
| `MANUAL_CHANGELOG` | Текст из поля `changelog` при ручном запуске **Automatic Changelog**. |
| `CHANGELOG_COMMIT_MESSAGE_FILE` | Временный файл с сообщением коммита. Его создаёт `run.sh`; вручную настраивать не нужно. |
| `CHANGELOG_TARGET_ID` | Имя файла цели без `.yml`, например `sunrise`. Передаётся при отправке в Discord. |
| `DISCORD_WEBHOOK_URL` | Сам адрес Discord из секрета, имя которого задано в выбранной цели. |
| `SOURCE_WORKFLOW_RUN_ID` | Номер успешного запуска **Publish Stable**, к которому относится сообщение в Discord. |
| `RELEASED_SHA` | Полный идентификатор опубликованной версии кода — хеш коммита. Рассыльщик определяет его по запуску Stable, включая откат, и передаёт отправителю Discord. |
| `TARGET_WORKFLOW_REF` | Ветка, из которой запускается отправка в Discord. Обычно основная ветка репозитория, `master`. |
| `GITHUB_OUTPUT`, `GITHUB_STEP_SUMMARY` | Служебные пути GitHub: передача значений между шагами и текст итогового отчёта. |
| `GITHUB_API_URL` | Адрес программного интерфейса GitHub. Обычно `https://api.github.com`; отдельно задавать не требуется. |

Обновление выполняет **Automatic Changelog**, проверку — **Validate Changelog**. После успешного Stable сценарий **Dispatch Discord Changelogs** запускает **Publish Discord Changelog** для каждой заполненной цели.
