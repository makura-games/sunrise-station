# Спонсорские вещи

Категория определяет правила получения вещи в игре. Продажа, цена и ограничения по профессиям задаются отдельно в каталоге сайта Stellar Stories.

| Категория | Что входит | Обычные способы получения |
| --- | --- | --- |
| `SponsorClassic` | Существующие вещи сборки, выбранные для спонсорского каталога | Разрешены карты, раздатчики, лодауты, подарки, хамелеон и артефакт |
| `SponsorExclusive` | Новые вещи, созданные специально для эксклюзивной спонсорской выдачи | Запрещены карты, раздатчики, лодауты, рецепты, наборы, таблицы выдачи, подарки, хамелеон и артефакт |

У предмета должна быть одна из этих категорий. Они объявлены в `Resources/Prototypes/_Sunrise/categories.yml` и наследуются потомками. Не добавляйте их общему базовому прототипу одежды.

В существующем прототипе достаточно указать:

```yaml
categories: [SponsorClassic]
```

Для новой эксклюзивной вещи:

```yaml
categories: [SponsorExclusive]
```

У `SponsorExclusive` задано `hideSpawnMenu: true`: вещь скрыта из обычного меню спавна. Создание по ID сохраняется для спонсорского инвентаря и административных команд. Не используйте `abstract: true` или глобальный запрет создания: инвентарь должен уметь выдать покупку. Сами категории не добавляют предмет в магазин.

Первые десять вещей и ещё 26 выбранных кандидатов относятся к `SponsorClassic`; их обычные источники получения сохраняются. Флотская фуражка, адмиральская форма, форма и обувь офицера спецопераций в эту подборку не включены. Летняя форма охраны (`ClothingUniformJumpsuitSecSummer`) и шорты СБ (`UniformSecurityShortsRed`) предназначены только для отдела `Security`: при добавлении этих товаров на сайте задайте `usage.departments: [Security]`. Это ограничение использования спонсорского инвентаря, а не покупки или обычного надевания найденной вещи в раунде.

## Проверка

```shell
dotnet test Content.IntegrationTests/Content.IntegrationTests.csproj --configuration Debug --filter "FullyQualifiedName~SponsorExclusive"
```

Тесты ищут ссылки на эксклюзивные прототипы и их наследников во всех YAML-картах и прототипах, учитывают старые ID из миграций, проверяют реальные пулы подарков и фильтры хамелеона и артефакта. Для `SponsorClassic` отдельно проверяется сохранение доступности. Отдельные тестовые прототипы проверяют защиту независимо от товаров каталога. `SponsorExclusiveClothingTests` проверяет, что каждую эксклюзивную вещь можно надеть на человека и что её присоединённые части создаются.

## Эксклюзивная одежда из подборки арт-директора

Вещи лежат в `Resources/Prototypes/_Sunrise/Entities/Clothing/Sponsor/`, текстуры — в `Resources/Textures/_Sunrise/Clothing/Sponsor/`, локализация — в `_prototypes/_sunrise/entities/clothing/sponsor/`. ID начинаются с `SunriseSponsor`.

- `SponsorExclusive` стоит только на продаваемой вещи. Шлемы, капюшоны и звенья МОДа помечены `HideSpawnMenu`: на эксклюзивный ID нельзя ссылаться даже из другого эксклюзивного прототипа.
- Графика взята из открытых репозиториев SS14; авторство, лицензия и источник записаны в `meta.json` каждой RSI.
- Механики исходных серверов не переносились. Защита повторяет штатную вещь, которую покупка заменяет при появлении; скафандры повторяют штатный скафандр профессии. У офицера ИСН своего скафандра нет: «Василиск» держит космос как скафандр ИСН, а броня у него как у штатного плаща-тренча.
- Покупка на сайте связана с вещью через `entityPrototype` в каталоге проекта. Если меняете ID вещи, поправьте `entityPrototype` в каталоге сайта, иначе купившие перестанут её получать.
- МОД — цепочка `ToggleableClothing`: блок на спине → корпус → шлем → перчатки → ботинки.
